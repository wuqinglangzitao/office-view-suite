# Office View Suite 预览优化实施计划

状态：2026-10-19 已实施并完成验收。P0、P1a、P1b、P4、P6、P2、P3 已完成；P5 未触发。实测证据和限制见文末。

## 目标和产品边界

保持现有 Rust/WASM 主解析链路，优先减少 Excel 大表的 DOM 与首屏开销，保证只读预览的布局、工作表切换与缩放体验。

- Excel 专项优化与共享 SDK 改进分别交付；各格式仅声明实际实现的能力。
- 保留 `open/clear/resize/destroy/on`、取消、替换请求、Worker 释放和宿主 DOM 所有权契约。
- 单元格/范围定位、选区、编辑、公式计算/交互、打印和导出不在本轮范围。普通浏览器文本选择和复制不受限。
- 文本搜索、页码/幻灯片导航为可选后续增强，不作为本轮完成条件。公式已有结果的只读显示仍须回归。
- 不增加生产依赖。`e-virt-table` 作为设计参考；本轮先利用现有 DOM renderer 实现有界渲染。`styled-exceljs` 只在实测证明有解析兼容性缺口后进行独立评估。

## 优化前机制与保留约束

- Excel 使用 `umya-spreadsheet -> Rust/WASM -> ExcelDoc`，入口为 `packages/viewer-excel/src/index.ts`。
- `packages/viewer-excel/src/core/render.ts` 初始创建全部工作表，按最高行列遍历；内容自适应列宽、自动行高和逐格展开的合并覆盖集合必须纳入虚拟化设计。
- `packages/viewer/src/index.ts` 在加载 adapter 前决定格式；格式预检必须同时覆盖该入口与独立 adapter。
- `scripts/prepare-sdk-assets.mjs`、`scripts/sdk-vite-config.ts` 已统一准备和输出资源；`scripts/browser-sdk-smoke.mjs` 已覆盖子路径与跨域 baseUrl。新增 manifest 复用这些机制。
- `scripts/visual-sdk-regression.mjs` 的 pre-SDK 基准用于显示回归，不能替代当前性能基线或独立解析期望值。

## 实施次序与阶段验收

### P0（高）：建立可重复基线

范围：新增专用 Excel 浏览器回归/基准脚本，复用真实样例；调整 `scripts/visual-sdk-regression.mjs`。

1. 固定 Chromium、1440×1000 视口、deviceScaleFactor=1，记录浏览器版本与运行环境。已签入的 XLSX 样例覆盖样式和合并；由明确 XML 生成的完整 XLSX 覆盖图片、富文本和公式缓存结果。两类文件都经过实际解析器；合成 DTO 仅用于隔离渲染性能，不能冒充端到端解析测试。
2. 固定小表、多工作表、10 万行×20 列稀疏表、宽表、自动换行、跨视口及巨大合并区域样例；记录有效单元格数和样式复杂度。保留生成方法，避免提交巨大二进制。
3. 首屏定义为挂载后完成两个 animation frame；记录加载/解析、DOM 挂载、首次可见、单元格 DOM 数、滚动后 DOM 数、切表和销毁结果。内存仅在环境提供可靠测量时记录，注明 JS heap 或进程口径，不能把缺失值当作零。
4. 同一环境预热一次、测量五次，报告中位数和最大值；冷启动的真实文件打开单独记录。原版全量网格超过 20,000 个潜在单元格时安全跳过，不给出原版耗时或速度比；其余浏览器操作设置 10 秒超时并关闭实例，避免基准耗尽机器资源。
5. 优化前锁定门槛：初始只挂载当前工作表；固定视口大表单元格 DOM 不超过 6000；扩大总行数不导致 DOM 等比例增长；小表首屏中位数不超过基线的 1.2 倍加 20ms。大表首屏上限 2 秒、切表上限 1 秒，按本机固定环境验收。
6. 视觉比较按标签逐个激活工作表再比较可见区域，不要求全部工作表完整 DOM 常驻。保留 pre-SDK 基准，另记录优化前运行结果；解析兼容性增加独立字段断言。

退出条件：基线、样例定义、阈值和命令可复现；如实记录原版失败或超时。

### P1a（高）：工作表懒挂载

范围：Excel `render.ts` 及专用浏览器回归测试。

- 初始只挂载首个工作表；切换时保存滚动位置、释放当前表资源，再挂载目标表。只缓存滚动和必要尺寸元数据，不累计已访问工作表 DOM。
- 保留标签、统计、可访问性状态；同表重复点击不重建。
- resize、替换文档、销毁应清理监听器、观察器和待执行帧。

验收：初始及切表后只有一个活动表内容；往返切换保持各表滚动；图片、形状、合并与冻结不回归；销毁后无渲染任务。

### P1b（高）：大表虚拟化

范围：Excel renderer、布局辅助模块、样式及针对性测试。

- 小表保留内容自适应布局，大表采用可见行列窗口与有界 overscan。阈值是明确策略，不在运行失败后静默回退到全量 DOM。
- 滚动前建立稳定尺寸索引，优先使用文档行高列宽；无显式尺寸的富文本、换行采用测量和缓存。不能随可见内容变化收缩整列/整行；字体、缩放和容器变化须正确处理尺寸缓存。
- 合并区域使用区间/相交判断，禁止按合并面积展开覆盖集合。主单元格在屏外但合并区域与视口相交时仍须显示。
- 图片/形状与单元格共享坐标索引，只挂载相交对象；冻结行列独立处理，冻结区域大于视口时仍保持有界 DOM。
- 滚动不得扫描全量单元格；更新以 animation frame 合并。
- 小表保持原来的 CSS 隐式轨道，合并/绘图扩展边界只用于选择虚拟化路径；字体重测完成后通知适宽重算。
- 对极密视口设置 20,000 个渲染节点保护，超过时明确报告 `RENDER_FAILED` 并清理，不截断可见内容。该限制与固定基准的 6,000 个单元格性能门槛分别记录。

验收：通过 P0 门槛；覆盖屏外长文本、换行、行列尺寸变化、跨视口合并、冻结交叉区、巨大合并、宽表及图片/形状；滚动和缩放后能访问末尾，无错位或旧表残留。

### P4（中高）：格式路由与有限预检

范围：`packages/viewer/src/index.ts`、`packages/viewer-core/src/index.ts`、独立 adapter 和测试。

- 无显式格式时，可识别内容优先于扩展名；未知内容不得仅凭扩展名通过确定性的签名/容器检查。
- 显式 format 与可识别内容冲突时返回稳定错误，不静默换引擎；独立 adapter 不得把其他格式送入自己的 Worker。
- 只预检明确的签名、容器边界、必要条目错误。PDF 深层对象、ZIP 解压或文档语义损坏由引擎报告 PARSE_FAILED，不承诺 WASM 前发现所有损坏文件。
- 延续现有错误码，诊断保留原因，不新增调试 UI。

验收：错误但受支持的扩展名、未知扩展名、显式格式冲突、缺失主条目、截断 ZIP、错误签名均在正确阶段处理；确定的预检失败不创建 Worker；有效签名但深层损坏可进入引擎并报告解析失败。生命周期和取消用例仍通过。

### P6（中）：只读缩放与适应容器

范围：公共查看器契约及适用 adapter；工作表切换和滚动保持归入 P1a。

- 增加固定比例和适应容器控制，明确参数校验并保持向后兼容。
- 能力查询仅返回实际实现的操作；搜索、页码导航和单元格定位不预留空实现。
- 缩放与虚拟视口使用一致坐标，容器变化后仍能访问完整内容，冻结、合并和覆盖对象保持对齐。
- 固定和适宽比例均限制在 0.1–4。Word 分页测量统一坐标，并提前计入后续分节宽度；PDF 采用 CSS 缩放，较大比例可能降低已有 Canvas 的清晰度。

验收：固定比例、适应容器、resize、切换文件和 clear/destroy 行为可测试；非法参数明确报错；无全量大表重建或宿主样式污染。

### P2（中）：内部 renderer 映射整理

范围：facade 内部加载表和实际能力描述。

四类 adapter 改为静态映射，保留动态 import、失败重试和缓存。不建立第三方插件协议；新增格式仍同步 OfficeFormat、内容识别和 adapter 验证。为已识别格式添加 adapter 时，加载主流程无需新增分支；能力查询随 P6 实现，不作为 P1 前置。

验收：四类格式路由、按需加载、失败重试、销毁和错误码回归通过。

### P3（中）：构建资产索引与部署校验

范围：现有资源构建、打包校验和浏览器冒烟脚本。

- 构建生成包含相对路径、大小和 hash 的部署索引，由打包校验脚本消费，避免无消费者的 manifest。
- 保留静态 new URL、显式 URL > baseUrl > 默认值以及 workerFactory 契约，不增加运行时加载器。
- 构建验证文件和清单；MIME/CORS 由受控 HTTP 正负场景验证，不保证任意部署配置正确，保留运行时失败诊断。
- 第三方许可证和 PDFium 材料继续随包输出。

验收：tarball 消费测试验证索引完整性和 hash；缺失/篡改资源失败；子路径和跨域正常加载通过，错误 MIME/CORS 由浏览器测试捕获。

### P5（中，条件触发）：解析器兼容性评估

仅在真实文件显示现有解析链存在未解决缺口时进行。无触发样例则记录暂不执行，不为完成计划引入新依赖。

只做 XLSX/XLSM 独立 benchmark，记录原始信息和统一 ExcelDoc 输出，使用同一 renderer。分离初始化、解析、DTO 转换/传输与首屏，逐项归因。本阶段不创建生产 fallback；是否采用 styled-exceljs 依据报告另行决定。

运行 `pnpm build`、`pnpm typecheck`、`pnpm test`、`pnpm test:packages`；渲染变化必须执行 `pnpm test:browser`、`pnpm test:visual` 和新 Excel 回归/基准脚本。PLAYWRIGHT_MODULE 使用已安装运行库，不新增生产依赖。

结果产物（不提交生成文件）：`output/excel-preview-results.json`、`output/playwright/sdk-results.json`、`output/playwright/visual-regression/results.json`。代码审查结论 APPROVE，独立架构审查 CLEAR；审查发现及修复见同目录审查记录。

最终渲染基准：Apple M1 Pro、macOS arm64、Node 22.15.0、Chrome 155.0.8059.82，1440×1000、DPR 1，预热一次后测量五次。下表耗时为首屏中位数（最大值），单位 ms，不包含 ZIP/WASM 解析：

| DTO 场景 | 基线首屏 | 优化后首屏 | 单元格 DOM（前 → 后） |
| --- | ---: | ---: | ---: |
| 40×12 小表 | 29.5（32.7） | 30.9（32.0） | 480 → 480 |
| 6 个 120×25 工作表 | 73.4（78.4） | 45.1（60.0） | 18,000 → 3,000 |
| 1000×20 表 | 393.9（424.2） | 57.1（80.2） | 20,000 → 527 |
| 100,000×20 稀疏表 | 安全跳过 | 31.0（31.6） | 未测 → 527 |
| 200×5000 宽表 | 安全跳过 | 31.8（32.1） | 未测 → 527 |

切到第二表及返回首表分别为 45.6ms、38.7ms，滚动位置恢复通过；跨视口合并、巨大合并、超大冻结区、末尾绘图均通过。小表未超过既定退化门槛。内存仅记录 Chromium JS heap 快照，不据此声称进程/WASM 峰值下降。

仍有边界：仅 Chrome 完成浏览器实测；复杂字体自动行高采用测量估算，未承诺与 Office 原软件一致；超宽表在最小 10% 比例仍可能横向滚动；极密视口触发保护；PDF 放大清晰度不等同于按比例重新栅格化。超大 DTO 的旧版基准被安全跳过，因此不报告旧版速度比。
